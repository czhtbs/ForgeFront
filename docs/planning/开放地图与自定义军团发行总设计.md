# ForgeFront 开放地图与自定义军团发行总设计

日期：2026-11-13。状态：已确认的未来版本设计方向，尚未实施；不代表当前游戏行为，也不替换现行联机与部署合同。

已确认决策：采用核心重写，直接替换旧玩法模型；主模式为 3–6 人自由混战，最后一座已完成核心被毁即淘汰，最后存活阵营获胜；核心位置始终遵循战争迷雾，允许隐蔽分基地；配件只限制不兼容组合，不设装配点数或总配件槽上限；全局只使用一种军备资源；取消固定阵形、站位与阵形操作，采用前排／后排软分组；服务器按总出站 3 Mbps、单房间最多 6 个玩家连接规划。当前仍处于计划阶段，游戏代码与线上服务不变。

2026-11-13，用户认可汇报中的补充玩法与发行内容方向，主要项目集中列在第 20 节。它们纳入后续实施依据；具体时间、费用、人数和性能预算仍为待实测调整的初值，不因设计获认可就成为已经验证的数值。

ForgeFront 的最终形态是以 **3–6 人自由混战、自定义兵种、混合军团和空间战术**为核心的实时策略游戏。玩家设计完整兵种，决定军团构成，在开放地图建立后勤支撑，再通过侦察、调动、包抄、断援和撤退争夺胜利。系统负责把完整士兵生产出来、送到正确军团，并可靠执行局部战斗。

本方案面向最终发行效果，不把目标缩减为最小可玩版本。实现按依赖拆阶段，但每个阶段都服务于同一完整体验。全部资源、代码、关卡、音效和检验流程均按 AI 可独立制作来选择，不要求人工建模、绘制方向帧、绑定骨骼或逐图修补。文中的人数、时间、费用与性能指标均为**设计目标或平衡初值**，尚不是测得结论。

## 1 游戏的决策中心

玩家反复做四类有价值的决定：这支军团要解决什么问题；用什么装备和比例解决；在哪里展开才能发挥；什么时候继续投入、换线或撤回改装。删除逐配件供货与手工连线后，省下来的注意力必须落在这四件事上。

| 层级 | 玩家决定 | 系统执行 |
| --- | --- | --- |
| 兵种蓝图 | 武器、效果、配件、防护、战术芯片 | 兼容检查、属性和成本计算、完整配装 |
| 军团编制 | 前排与后排各包含哪些兵种、人数、补员优先级 | 缺额计算、排产、归队与后排跟随 |
| 战场指挥 | 路线、目标、坚守和撤退 | 移动、局部避障、索敌、接敌、有限追击 |
| 基地经营 | 建筑落点、扩张方向、经济与军备投入 | 自动连接、设施工作、增援运输 |

明确取消：固定领土所有权、每地块一个建筑、逐装备工坊、手拉供应线、未配齐即出征、单兵调度、按装备组合生成地图军标。保留并加强：枪与剑的组合系统、弹道联动、护甲取舍、军团级箭头命令、资源点、关键据点和可被攻击的生产依赖。

发行范围以一套对称规则为主：玩家共享装备库，差异来自本局蓝图与部署，不额外制作六套阵营科技与兵种。没有永久数值养成，不让局外解锁决定对局强弱。不同外观与徽记可以存在，但不承担战斗优势。

## 2 一局游戏的完整体验

开局拥有基地核心、基础军备、基础兵营与一支完整的预设军团。玩家可以直接出发侦察，也可复制预设稍作调整；不强迫每局从空白编辑器开始。

前期争夺邻近矿点、观察敌方构筑，建立第二条行军路线。中期用混合军团夺取关键据点，决定投资兵力、研究还是前线节点。后期通过保护补员通道、打断敌方生产、轮换受损军团与针对性改装维持战线，再侦察并摧毁敌方全部核心。最后存活的阵营获胜；据点和资源服务于军事进攻，不提供胜利积分。

一个代表性局面：正面军团由重装剑兵、普通步枪兵和少量抛射兵组成，固定敌方正面；轻装机动军团沿林缘绕行，摧毁敌人的支线节点。敌方现役部队仍能战斗，但前线兵营停产，安全补员点退后。此时玩家选择推进截断退路，或先占点迫使对方进攻。双方取舍来自阵容与位置，不要求任何一方去点选散落的补员士兵。

| 项目 | 建议目标 | 目的 |
| --- | --- | --- |
| 主模式 | 3–6 人自由混战 | 支持第三方介入、换线和分散侦察 |
| 常见对局时长 | 25–45 分钟的节奏目标 | 留出观察、改装与多轮战线变化；不按时间强制判分，隐蔽基地与持续攻防可能延长对局 |
| 常用主力军团 | 每人 4–6 支 | 允许同时打正面、侧翼与守家 |
| 单军团人数上限 | 60 | 支持 A10＋B20＋C30 的直观编制 |
| 军团上限 | 每人 8 支 | 容纳小型侦察队，控制指挥与图标数量 |
| 全部人员上限 | 每人 240 | 含在队、在途、储备和已开工预留名额 |
| 内容规模 | 2 类基础武器、现有核心效果与配件 | 深化组合而非靠新增大量单位填充 |

这些数量不是规模越大越好。若六方混战无法同时满足可读性与运行预算，应先调整人数和弹体密度，不削减军团功能，也不暗中限制实际参战人数。

## 3 兵种蓝图

### 3.1 三种对象必须分开

**兵种蓝图**描述一名完整士兵；**军团模板**描述前排／后排各兵种的目标人数；**实际军团**保存当前成员、命令、损失、补员及装备版本。相同蓝图可被多支军团使用，也可分别加入同一军团的前后两组，无需复制蓝图；相同军团模板可用于创建多支独立军团。

蓝图有稳定 ID、玩家名称、自动生成的徽记、已发布版本和未发布草稿。实际士兵记录生产时的装备版本。玩家给蓝图改名、升级版本或出现旧新版混装，都不改变军团的地图身份。

### 3.2 保留组合空间并建立真实取舍

| 部位 | 建议规则 | 战术作用 |
| --- | --- | --- |
| 主武器 | 步枪或剑，必须选择 | 决定接敌方式与基础轮廓 |
| 附加效果 | 炸药、电弧、燃烧、冰霜中至多一种，也可留空 | 即时伤害、穿甲价值、区域限制或控制 |
| 武器配件 | 沿用穿透、弹跳、分裂、返航、追踪、滞留、留痕、延时、抛射 | 改变命中结构和发挥条件 |
| 远程防护 | 无、轻、中、重 | 抵抗远程，付出军备与速度代价 |
| 近战防护 | 无、轻、中、重 | 抵抗近战，付出军备与速度代价 |
| 战术芯片 | 至多一种，可留空 | 调整局部距离或目标选择 |

现有武器兼容关系继续生效，诸如剑不装远程专用配件、抛射保留最小射程与近敌压制。空的可选槽是完整设计的一部分；“玩家没选护甲”与“护甲还没送到”不再混淆。

配件不设置总装配容量或总槽数限制。每种配件按是否安装表达，不开放同一种配件无限重复堆叠；只要组合兼容，就允许同时安装。武器、附加效果、防护和芯片自身的互斥关系继续有效。复杂组合通过整兵造价、生产工时、攻击准备、重量或战场适用性付出代价，不用隐藏点数上限缩减组合自由。

高级配装至少付出三项可感知代价中的两项：更贵、造得更慢、机动或近战应对更弱。基础步枪必须始终有性价比价值，重装不应只是全方面升级。重复产出、分裂和持续触发的组合，要检查整次攻击的总作用量及生成数量；不能让每个乘数都全额复制而费用只做线性相加。

### 3.3 发布与版本

编辑只改变草稿。点击“发布”后，未来未开工需求使用最新版本；已经开工的生产任务、已经出厂和已经在途的士兵保持锁定版本。现役旧版不会凭空换装，需要返营付费改装。

发布前只列实际变化：单兵军备、生产工时、移动速度和受影响军团，以及“现役旧版 18，在产旧版 2，后续 V3”。不弹一整页流程解释，也不因为每次修改都要求额外确认。

科技未解锁的组件可以在局外蓝图库中保存，但本局不能发布为可生产版本。提供“另存蓝图”用于只调整某支军团，避免无意影响所有引用同一蓝图的军团。

### 3.4 预设与验证

发行时提供约 8–12 个可直接使用、可完全编辑的预设，覆盖基础步枪、重装前排、轻装机动、抛射支援、反密集与控制等职责。预设不是额外职业系统。

编辑器显示生命、防护、射程、移动速度、攻击间隔、造价和工时。范围效果另给标准场景结果，例如“稀疏轻甲”“密集轻甲”“少量重甲”，不制造一个混淆一切的总战力分。测量使用实际战斗代码；估算与训练场实测分开标识。

## 4 混合军团与指挥

### 4.1 配比就是生产承诺

军团编制以整数为主，分为前排和后排两个列表，例如前排 A 重装剑兵 10、后排 B 步枪兵 20 与 C 抛射支援 30。允许直接输入和加减，比例条只作辅助，不用难以精确操作的纯百分比滑条。同一蓝图在前后两组分别统计需求，每名实际人员只计入一个编制行。

每行分别显示在队、在途、在产、待产和目标。旧版人数是现役人数中的子集，不额外相加。排产缺额为：

`max(0, 目标人数 − 在队 − 在途 − 已分配储备 − 已开工人数)`

待产只是需求，不扣款也不预占实际人员。开始生产才同时扣除完整造价并预留一个人口名额。所有已存在人员计入人口，包括暂存兵营的储备，避免用后台仓库绕过上限。

### 4.2 前排与后排软分组

不建立固定站位、横列／纵队／疏散模式、队形宽度或玩家指定朝向。玩家只往前排与后排添加“兵种×人数”；成员可以自然散开、绕障碍和因交战打乱位置，不为恢复整齐队列而重新分配站位。

前排沿军团命令路径按各自移动能力尽快推进。后排在相同路径方向上参考前排群体的推进位置；当前排尚未处在其前方时主动减速或短暂等待，前排领先后继续跟进。不会把全军速度硬锁到最慢成员，也不保证每名后排身前都一直有一名掩护者。

前后关系依据本次移动或进攻的路径方向，不依据画面的上下，也不因敌人从后面出现而瞬间交换职责。后排可以自卫，但不会自动绕到整支前排背后获得保护；后方突袭、转向时的暴露和前排被牵制都是可利用的局面。交火时攻击距离、局部避障与自身武器规则优先，不为维持前后次序让已接敌成员来回跑。

执行边界建议：没有存活前排时，后排正常执行军令，不永久等待；撤退时以各自速度脱离，不为重新建立前后关系停下来；前排受阻时后排可以暂缓推进，成员仍能在当前位置战斗，玩家可用整团改令或撤退处理。近战追击与芯片距离调整继续受局部活动范围约束，不新增自动包抄或自动换位。

实现时按军团低频更新共享路径和前排推进参考，成员只做简单跟随判断与必要的局部避障，不把所有前后排成员两两比较，不为保持分组每步重新全图寻路。拐弯时参考共同路径走廊，不能只用跨过山体的直线判断谁在前。该方案主要减少站位维护和操作复杂度，实际计算节省仍需测量。

### 4.3 玩家命令

| 命令 | 结果 |
| --- | --- |
| 移动 | 优先到达落点，不因路边目标长距离停留 |
| 进攻 | 沿指定路线推进，前排先接敌，后排尽量跟在其后并按自身射程作战 |
| 指定攻击 | 优先处理敌军团或建筑，成员选择合理局部目标 |
| 坚守 | 留在指定区域作战，不保持固定站位，也不被一个诱饵拉离据点 |
| 撤退 | 沿可行路线返回选定整备点，优先脱离；无无敌或免费加速 |
| 返营改装 | 返回有效兵营并按已发布蓝图整备 |

所有射程，包括抛射，都使用同一进攻入口。射程外自动接近，近敌压制时按局部战斗规则执行，不增加独立炮击选点模式或固定炮兵阵位。

多选军团可下同一条推进命令，各军团仍保存身份。地图点到一个成员，也只选中其所属军团。战场不支持“把所有同型号枪兵抽出来”或临时框选半队，这会重新引入单兵微操。

军团拆分、合并与人员转移只在同一安全整备范围内执行，以整行数量操作，人员真实移动并重新归属。途中不允许反复拆合改变补员落点。纯粹一起行动使用热键编组，不需要合并军团实体。

## 5 空间战斗

### 5.1 开放地图的战术要真实发生

所有成员、射程、弹体与建筑使用同一世界坐标。跨越过去的地块边界不再触发独立战斗、切换比例或把多余士兵塞进预备队。地形上有多少成员，多少成员就实际参与战斗。

包抄首先通过位置奏效：从侧后方接近后排，避开正面火力，增加近战接触面，切断退路，迫使敌军改变移动和攻击目标。前后软分组不自动修补被绕后的弱点。不要先用看不见的“侧击伤害加成”代替这些空间关系；本方案不增加定向盾牌、阵形加成或玩家手动调整防御朝向。

### 5.2 地形职责

| 地形 | 规则 | 产生的选择 |
| --- | --- | --- |
| 开阔地 | 通行空间大、视野清楚 | 射程和接近路线有价值 |
| 林地 | 降低视野与通行速度，边缘轮廓明确 | 隐蔽调动、近战接近、绕行时间 |
| 岩体和建筑 | 阻挡移动与直射 | 绕射界、截击、保护生产 |
| 山脊和坡道 | 山体阻行，坡道提供明确入口 | 控制通路与分兵防守 |
| 水域 | 阻行，桥或浅滩提供固定通过位置 | 形成可以观察和争夺的交通点 |
| 据点周边掩体 | 按明确掩体区域降低直射命中，抛射有对应价值 | 防守位置、侧向接近、火力构成 |

地形属性由规则数据决定，画面如实表达。装饰草丛不伪装成掩体，装饰小石头不随机卡兵。高处主要提供视野与射界，不叠加大量隐藏攻防系数。

直射需有清楚的地形遮挡规则；建议己方人群不阻挡普通枪弹，避免混编反复卡枪。敌人可被穿透、弹跳等现有机制作用。建议不引入友军伤害，使混编自动作战可预测；范围武器的代价通过造价、时间、稀疏目标效率和近敌压制承担。

### 5.3 战争迷雾与构筑信息

地图地形、资源点与战略据点位置开局已知；敌军与建筑需要侦察。最后目击的建筑保留灰色记号，移动军团不在迷雾中保持精确追踪。

敌军进入视野后可读出武器大类、护甲轮廓及已观察到的效果。选中可见敌军可查看已观察到的组成，未知组件显示未知。不给所有敌军免费公开完整蓝图，也不要求玩家只凭几像素粒子猜全部克制。所有敌方核心始终遵循相同迷雾规则，包括只剩两方的残局；不会自动公开位置、总数量或精确存活状态。允许隐蔽分基地，也接受侦察最后一个基地可能延长对局的取舍。

补员队不占点，不独立贡献战略视野，不提供可操纵侦察能力；它们使用己方已知区域与局部遇敌信息移动。系统不使用未发现的敌军位置为它们规划神奇的安全路线。

## 6 自由建造与自动后勤

### 6.1 后勤是设施支持关系

军备是阵营统一预算，不再模拟每箱装备的位置。物流网络表达生产、施工与部署能否得到基地支持。因此一座独立核心可以使用阵营预算独立工作，不需要给每个分基地再建一个材料仓库。

基地核心是网络根。物流节点自动连接限定范围内、地形通路合法的己方核心或节点。连接条件是有限支援距离与地形可达，不是“随便找一条跨全地图的路”。同一个阵营可以有多个独立根。

尽量只让玩家理解一种支援半径 R。节点之间的可通行距离不超过 R 才连边；建筑中心处在有效节点的支援距离内才能工作。覆盖形状按山体、水域等裁切，不能只画一个穿山的圆。自由选址仍可使用隐藏的小网格进行占地与寻路计算，网格不表示领土或建筑地块。

一个设施只需受到至少一个连接到存活核心的节点支持。某节点被毁后，如果另一个真实建造、付出成本的路径仍然存在，网络继续工作。这种冗余是合理防守投资，应保留；要删除的是原来免费换一条领土运输路线的结果。

### 6.2 断网后果

| 对象 | 所属连通分量没有核心时 |
| --- | --- |
| 兵营 | 暂停生产、改装与休整，保留已付款任务和进度 |
| 矿场 | 暂停收入 |
| 研究室 | 暂停研究，已完成科技不倒退 |
| 在建建筑 | 暂停施工 |
| 物流节点 | 不提供扩建与网络部署，实体仍可被攻击 |
| 防御设施 | 仍能自卫，不能依靠离线无限修复 |
| 已有军团 | 正常移动和战斗，不凭空失去伤害或生命 |

节点恢复后需要短暂启动，建议 5 秒。断网不销毁订单，不凭空退款，不把现役士兵变成无武器单位。网络变化只在节点或地形状态改变时重算。

### 6.3 扩张的代价

新节点只能从已有有效支持范围边缘向外建造；未完成节点没有覆盖，不允许一口气摆一串蓝图立即穿过整张地图。节点建议需要约 20 秒建造，具有清楚的轮廓和受攻击窗口。施工地点必须在己方当前视野内。

建筑放置检查占地、地形与出入口。基础规则允许利用建筑组织基地形状，但不能把生产出口封死。敌军近身交战区不能直接新放建筑，使用一个明确的建设警戒距离，避免在部队脚下瞬间刷出障碍；已开工建筑不会因敌人靠近自动消失，只能被攻击。

分基地核心成本和建造时间显著高于节点，建议相当于数座兵营、约 90 秒建设。新核心与其他建筑一样，开工及施工期间需要已有有效网络支持；完成后成为独立根，不再依赖原连接。隐蔽分基地通过隐蔽扩张建成，不能在任意已探明地点远程开工。它既是独立生产支点，也是值得进攻的目标。多核心不重复提供基础军备收入，避免把防断网设计变成无风险经济建筑。

### 6.4 建筑目录

| 建筑 | 最终职责 | 不承担的职责 |
| --- | --- | --- |
| 基地核心 | 独立支持、施工调度、阵营存续 | 不生产逐类配件，不按数量叠基础收入 |
| 物流节点 | 延伸覆盖、形成冗余、提供网络出口 | 不让玩家选产物或编辑连接线 |
| 兵营 | 完整士兵生产、储备、补员、休整、改装 | 不分别等待枪、弹、甲到货 |
| 矿场 | 在固定矿点获取军备 | 不生成可手拉路线的货箱 |
| 研究室 | 解锁组合与有限通用强化 | 不替代蓝图，也不让多座免费倍增研究 |
| 防御塔 | 提供局部基地防卫 | 不代替移动军团争夺远处据点 |

每个核心提供固定施工并行能力，建议同时一项；多个核心扩大施工面，但不让一个基地瞬间落成十个前沿节点。兵营独立生产，研究室提供研究队列。生产、施工、研究不另加电力、工人、燃油和维护费系统。

## 7 军备经济与完整生产

### 7.1 只使用一种可花费资源

全局统一为一种可花费资源“军备”，这一方向已确认：造建筑、造完整士兵、研究和改装都花军备。人员上限若采用，只是规模限制，不是需要补货的另一种资源。这样每次损失都与扩张和科技直接竞争，同时不会恢复一条隐藏的材料流水线。

阵营只要有至少一个已完成、存活的有效核心，就获得一份较低基础收入；额外收入主要来自受支持的矿场。正在建设的核心不提供收入或支持。建议常规经济中基础收入约占 20%–30%，确保失去矿点后仍有有限行动空间，但无法靠缩在基地赢得经济。矿点本局不枯竭，空间争夺由地图和胜利目标驱动。

矿场建在固定资源点上；攻击者摧毁敌矿后，需要建立自己的支持并建设矿场。矿点不会因为一名路过士兵就无成本转交全部建筑。中立据点提供位置优势，推荐作为可占领的中继站复用节点规则，不提供胜利积分；占领规则见第 10 节。

### 7.2 定价和排产

单兵成本由身体训练、主武器、防护、效果和配件构成；完整生产工时由相同内容表给出。高级联动的费用与工时可以按明确组合修正，但必须在编辑器总额中体现，不设玩家无法解释的随机售价。

每个兵营一次生产一名完整士兵，多座兵营自动接单。优先使用与目标军团相同物流分量、交付时间较短的兵营；相同条件使用稳定规则裁决。军团只需设置“正常／优先／暂停”，无需逐兵营排六十个订单。

同一优先级中轮转服务军团，再优先补足该军团完成比例最低的兵种行，完成比例包含在队、在途和在产。昂贵兵种所需资金尚未够时，为当前选定任务积累预算，不无限用便宜兵吃光余额。最高优先军团不能永久吞掉其他正常军团的所有产能，采用简单有界的优先轮转。

多个来源生产的士兵都必须完整符合各自版本。A 先到、C 后到可以造成军团暂时缺员，但不会造成一个士兵缺武器或缺护甲。对新军团，默认在兵营集结到玩家设置的出发人数再投入使用；出发本身仍由军团级命令决定。

### 7.3 付款与取消

开工一次性支付完整成本，任务保存已付款额与进度。未开工需求取消没有损失。已开工主动取消，按尚未完成比例退还；已消耗部分不退。兵营被摧毁时，其中未完成生产及实体储备随建筑损失，不能自动完整迁移到另一座兵营。

下调编制不会删除现役人员。未开工需求自动减少；正在生产者可以按规则取消，已完成和在途者先保留为该军团的超编或基地储备，返回整备区后统一转编。超编不再额外补员，仍计人口。在安全整备区可按编制行把富余 A 人员转为缺额 B 人员，再按改装费用完成 B 的完整配装，不需要先空出人口造一个新人；改装完成前仍按旧装备作战。这是军团编制操作，不开放单兵调度。另允许在整备区按行退役富余人员，释放人口但不退还已消耗军备。

不提供反复造兵、拆装备、解散而获得正收益的回收循环。取消、销毁、转编、改装和退款必须共享同一本军备结算记录。

## 8 自动补员与战线

### 8.1 补员便利不能取消战损价值

军团设置一个集结落点，默认跟随其后方。补员有真实生产来源、任务编号、所属军团和锁定蓝图版本。网内运输可抽象表现，但身份、耗时、人数和中断后去向都是正式模拟状态。

**不采用在交火中心无条件即时刷兵。** 这会把包抄、冲锋和撤退压缩成收入对耗，也使无限贴脸补员成为最强防守方式。

### 8.2 物流网内

网络部署要求生产兵营与目标处于同一个有效物流连通分量；两个互不相连的核心之间不能无条件瞬间互送。目标落点还需当前己方可见、可通行、有空间，没有已发现的近身敌人或危险持续区域。

军团停止交战并在安全集结点稳定停留后才可直接接收，建议稳定 8 秒。运输时间按网络路径长度计算并有非零最小值，建议最短 4 秒；按小批次逐步加入军团，不在同一帧把库存全部投到前线。

若军团正在战斗或移动，补员在其后方最近的安全网络出口落地，再步行追赶。军团不必退回基地，但战斗中始终有可被截击的最后一段路。这保留了用户期望的网内部署便利，也保留了真实交战窗口。

网络运输记录实际可通行路径、当前路段和进度；正常期间省略实体展示，敌方通过攻击节点影响它。连接失效时，路段中的批次在该进度对应的可通行位置实体化，进入补员行军；不会倒回兵营、越过断点或继续享受网络运输。停在失联节点的人员从节点出口实体化，出口受阻则保留为该节点储备；节点本体被毁时其中储备全部损失。实体化后的人员寻找可达安全基地或等待恢复。费用与身份只结算一次，不能复制一份回基地，同时让另一份继续抵达。

### 8.3 物流网外

从合适兵营或有效网络出口发出补员队，建议按 3–6 人或最多等待 6 秒成批。补员队自动追随所属军团的预计会合点，不追逐某个成员的即时坐标。

补员队可以被攻击、被拦截和消灭，会自卫，但不能由玩家单独选中、下攻击命令或拿去占点。地图常态不为每批显示永久徽标；选择其所属军团时才显示路线与在途计数。

系统依据已知危险选择路线，不用全知敌情绕路。安全路径不存在时，停在后方安全点并显示“补员受阻”；遭遇伏击时尽量退向来路。不得一人一人无限重复走入同一个已发现火力区。

军团跨入、跨出覆盖区不会清除或复制在途人员。已经实体化的补员不重新吸回网络以跳过敌人，继续真实行军。目标改变后低频更新会合位置，避免每个成员每帧单独全图寻路。

### 8.4 团灭与重建

军团所有在队成员死亡后转为“待重建”，保留名字和编制。取消继续向旧前线坐标送兵；在途成员返回可达安全整备点，在产任务转入储备或由玩家按正常规则取消。

点击军团级“重建”并选有效兵营后，现有储备重新集结，新生产补足缺额。空军团没有视野、不能占点，也不能充当移动的隐形空投坐标。

## 9 返营改装与科技

军团返抵安全兵营后，按成员逐步改装到所属蓝图最新已发布版本，或改编时指定的新蓝图。改装使用兵营生产能力，与造新兵竞争；部分完成时可以被命令中断，已完成者保留新版本，未完成者保留原配置。因离开整备区而中断的在办任务结束，按未完成工时比例退还改装费用，已消耗部分不退；再次改装从新任务开始，不能带着同一个进度同时在两座兵营施工。仅因断网暂停且人员未离开时保留付款与进度。

建议费用为“新增加的装备成本＋新完整配置一定比例的改装工费”，工费初值 10%。相同装备不重复付费，拆掉的装备不按全价退回。改装对象在开工时锁定版本，期间再发布新版只影响后续未开工改装。

改装保持生命比例，不免费恢复满血。安全兵营中的休整按缺损生命比例消耗军备，采用固定时间恢复，成本低于重造同一个兵。撤退到整备点默认开启休整；界面以单独费用和进度表达，防止玩家误以为改装费包含免费治疗。

科技继续保留效果、装备解锁与通用强化三个易理解方向，但削减纯数值层层碾压的权重。关键研究应打开新的组合或改变投入选择；基础武器在后期仍有低价快补价值。已研究的科技是阵营状态，不因研究室断网消失。

局外蓝图库不跨局携带科技优势。本局修改可另存为预设；下次对局仍需满足本局解锁条件。研究不能在局中强行修改已存在蓝图的槽位合法性，规则变化留到对局版本更新。

## 10 自由混战的地图与胜利

### 10.1 地图不能只围绕一个中心

三人地图可从 3 个关键据点、四至六人从 5 个开始试验，具体数量按通路与进攻纵深调整，不为计分均分地图。分布形成环线与横向通路，避免所有人只挤进中心一个洞口。出生区域至少有两条可用出口；邻近矿提供起步经济，争夺矿位于外环或侧线，不让最富矿点与唯一主要通路重叠。

从开局基地到邻近争夺区的行军时间建议约 30–60 秒；横穿主要战区约 90–150 秒。地图距离以基础军团行军时间校准，不能只按像素大小决定。六人版增加可并行战线，不仅把三人图等比例放大。

发行地图采用受约束的程序生成：先生成出生区、主通路、侧路、矿与据点，再添加地形。自动检查每个出生点的出口、资源可达时间、到据点的路线数量与建设面积。通过条件的固定种子组成正式地图池；另提供随机地图供自定义房间使用。不要把未经检查的任意噪声地图直接当默认对战地图。

### 10.2 歼灭胜利与核心存续

最后一个未淘汰的阵营立即获胜。阵营必须始终保有至少一座已完成且存活的基地核心；最后一座核心被摧毁时立即淘汰，不要求攻击者继续清理散兵、矿场、兵营或防御塔。没有覆灭倒计时、紧急兵营转核心或战败后复活。

普通分基地在阵营存活期间可照常投资建造。在建核心不能维持阵营存续。固定模拟步内先结算施工完成，再结算战斗伤害及摧毁，最后统一检查各方存活核心并判定淘汰：本步已经完成且经战斗后仍存活的新核心计数，尚未完工的核心不计数；不能在淘汰后继续施工补救。所有阵营统一结算，不按玩家编号逐个提前宣布胜利；同一步所有剩余阵营均失去最后核心则平局。

被淘汰者的军队退场，建筑和在建任务停止工作，所持中立据点释放，资源不转交最后攻击者。战斗统计保留击杀记录，但最后一击不额外授予经济、建筑归属或胜利积分。正常对局不设置计分模式、缩圈、强制揭露核心或按时间判定军事价值；25–45 分钟仅是平衡目标。

自由混战不默认共享网络、资源或视野，也不增加外交条约系统。第三方可以趁虚而入、临时合攻或改变攻击方向；规则减少抢最后一击的额外收益，但不承诺消除第三方介入的影响。

### 10.3 关键据点与攻防节奏

推荐把关键据点统一为中立中继站。占领后复用物流节点的覆盖、自动连接和补员出口规则，必须连接己方存活核心才工作；孤立占领不提供免费远端建设，不产生独立收入，不算核心，也不能避免淘汰。矿点继续承担经济职能，不新增第二套积分或成长资源。

军团实际战斗成员进入小范围占领圆并停留，完成占领初值 20 秒，不按人数加速。敌方进入时据点暂时争夺，停止提供支持；仅一方留在圈内时推进该方占领或恢复，互相敌对的多方同时在圈内则暂停。军团徽标、远处火力和在途补员均不算占点；圈内禁止放置建筑。己方稳定持有后可以离开，归属保留到被重新占领或所属阵营淘汰。中继站本体为地图设施，靠占领更换归属，不进入可摧毁建筑列表；玩家建设的建筑均可按建筑伤害规则摧毁，包括核心、节点、兵营、矿场、研究室与防御塔。

据点位置开局已知，敌方归属和运行状态按视野与最后目击显示，不泄露隐蔽基地的连接。其价值是前线位置、通路与补员距离，而不是一个与战斗无关的胜利倒计时。

防止纯守家依靠多数收入来自争夺矿点、攻城配装能逐步拆解静态防线、机动军团能切断前线支持，以及防御设施不能免费抵消持续围攻。先验证这些关系，不额外添加维护税、逆风奖励或强制末日事件。歼灭模式加上隐藏核心允许长局；不能为了维持时长目标暗中改成积分结算或公开敌方核心。


上栏只保留军备、净收入、人员名额、存活阵营数、己方核心状态和时间。不显示敌方未发现的核心数量、位置或精确生命。军团名单显示编号、短名称、在队／目标和一个最高优先状态。单击选择，双击定位，数字热键选择军团或编组。

小地图必须清楚区分六方，展示己方核心、已探知敌军、资源与据点。颜色同时配合轮廓、编号或形状；不只靠红绿。核心受袭与阵营淘汰使用短提醒；不通过排行榜或全图标记暴露未侦察到的军队和分基地。

### 11.2 一支军团一个地图徽标

| 缩放层级 | 显示 | 隐藏 |
| --- | --- | --- |
| 战略远景 | 军团徽标、规模、据点与已知基地 | 单兵、配件标、普通弹丸 |
| 常用战术景 | 军团轮廓、简化成员、重要弹道与危险区域 | 每兵血条、所有装备文字 |
| 近景 | 身体与武器、防护轮廓、动作和命中 | 单兵名字及悬浮装备卡 |

地图徽标数量与军团数相关，和兵种种类、版本数量、补员批次数无关。重叠时对徽标避让；不同阵营不能合并成一个含混标记。单兵血条仅在必要时短暂出现，军团详情显示汇总伤势。

军团选中条显示名称、当前人数、目标人数、在途人数、组成条、状态和基本命令。点击组成条打开编制，不在战场浮层里长篇列出每个组件。

### 11.3 建造与物流

建造保持两列图卡、静态示意图与短名称。选择建筑后显示真实占地、出口、新增支持覆盖和自动连接。合法性以颜色加图形表达，原因只用短状态，例如“无支持”“通路阻塞”，不用说明段落。

正常战场不显示整张物流网。选择节点时显示相关连接和依赖设施，开启物流图层才显示全网。提供选中节点的失效预览，高亮“仅经此节点获得支持”的建筑；拥有备份支持的建筑不误报。

一条支线断开只产生一条聚合提醒，例如“东线中断 · 3 座设施”。点击后定位受影响区域，声音也只播一次。网络重连、生产完成等低优先事件不持续打断战斗。

建筑选中面板保留名称、等级、生命与必要状态；兵营显示当前生产、储备、整备任务，节点显示支持关系。旧“可装备人数”和工坊产出在新系统里退出。实施时应同步修改项目约定中的对应 UI 条款，继续保留无教程段落、无重复建筑大图的要求。

## 12 两个编辑器

### 12.1 兵种编辑器

三栏结构：左侧蓝图库，中间装备人形与槽位，右侧成本与对比。点击槽位才打开该类组件，不一次堆出全部图标。组件选择实时更新纸娃娃、参数变化、总军备与工时。

多人对局不暂停，编辑器以可收起侧面工作区为主；核心受袭与阵营淘汰提醒仍可见。关闭保留草稿，不自动发布。高级对比和试战放局外训练场，避免正式对局同时运行另一套战斗模拟。

交互顺序为：复制预设 → 改名称 → 选武器与效果 → 调配件和防护 → 查看成本与速度差值 → 发布 → 加入军团编制。常见修改不要求重新走完所有步骤。

禁配组件保持可见并显示短原因；需要长解释时打开独立图鉴或教程。装备规则与参数从模拟同一数据计算，不能在 UI 再写一份看似相同的公式。

### 12.2 军团编制编辑器

左侧选择军团或模板，主体仅有前排和后排两个编制区，旁边显示汇总。每区用“兵种×目标数量”添加成员，在队、在途、在产等状态按需展开。同一兵种可以分别放进两区，不需要拖到具体坐标或复制蓝图。

删除阵形点阵预览、宽度与朝向控件。可以用两条人数构成条表达前后排配比，不把它画成实际战场站位。汇总显示整军成本、缺额成本、人口与各组成员速度范围，不显示一个保证全军齐步的速度或固定队形占地。

“应用编制”改变目标，“发布蓝图”改变未来装备，“返营改装”改变已有人员，这三个动作必须使用不同名称，避免一个“保存”按钮暗中做三件事。

补员提供正常、优先、暂停。集结点、撤退基地与返营改装在军团层操作；兵营队列主要用于观察和必要时取消，不能重新成为玩家逐项维护的主界面。

## 13 美术与声音

### 13.1 采用高机位二维战术沙盘

不建议直接改成传统等距人物视角。斜视人物如果仍旋转一张图片，会出现身体侧翻；真正解决需要方向素材或三维模型，会违背生产约束。

保留成员的高机位俯视轮廓和任意方向旋转，通过地形高差断面、建筑固定机位立面、统一投影、遮挡和动作赋予体积。镜头固定方向，可缩放和平移，不做自由旋转。画面可以具有厚度，但战斗平面和可见射程仍保持清楚。

制作优先级是轮廓可辨、空间可读、反馈有力、风格统一，最后才是更多装饰。纯俯视不必然简陋，缺乏层次、反馈和一致性才是当前更可解决的问题。

### 13.2 资产生产方式

| 资产 | AI 可独立完成的生产路线 | 发行要求 |
| --- | --- | --- |
| 士兵 | 现有头、躯干、手臂、护甲、武器分件，程序拼装与动画 | 武器与防护在常用缩放仍能分辨 |
| 建筑 | 每类一张统一机位透明主图，程序加阵营色、底座、阴影和损伤 | 占地与画面相符，六方识别一致 |
| 建造卡 | 少量 AI 母图统一裁切压缩 | 同尺度、同光源、同留白 |
| 装备与科技图标 | SVG 几何图标 | 可缩放、风格统一、无需每种组合新图 |
| 地形 | 程序材质、岸线、断面、道路与少量树石母图 | 可通行、遮挡、掩体一眼可辨 |
| 战斗特效 | 枪口、轨迹、命中、持续区等少量图元程序组合 | 不遮掉部队和危险边界 |
| UI 纸娃娃 | 沿用 SVG，随装备显示分件 | 与实际配置一致，不追求写实角色立绘 |
| 音效 | 程序合成和少量 AI 音色生成 | 武器、命中、完成和告警分层，限制同时发声数量 |

建筑使用固定姿态；如果功能不需要旋转，不做四方向建筑资产。建造进度用程序显现，损伤用烟尘、焦痕和少量碎片，不给每个生命阶段生成一张新图。部队组合只改变分件和弹道，不为每种蓝图生成整套士兵素材。

建议母版规模约为 6 类功能建筑、少量中立据点与树石、2 种武器轮廓、现有护甲分件、现有组件 SVG，以及一套基础粒子。完整配置组合可以非常多，母版数量不随组合数相乘。

### 13.3 动作与声音优先于新增插画

行走使用足部节奏、轻微躯干起伏与落地影；射击使用后坐和枪口；挥剑使用清楚的武器弧线与接触反馈。重装转向和移动显得更沉，轻装更利落。动作频率跟真实攻击节奏对应。

特效有视觉预算：主攻击读得清、区域伤害边界读得清、普通装饰能降级。单位阵营色和血量信息不被彩色粒子淹没。持续效果用稳定边界和低强度内部运动，避免全屏频闪。

声音按镜头距离、事件重要性和同类并发限制混音。多人齐射不逐兵播放完整响声；节点中断、基地受袭、军团濒危有短而不同的提示。关闭音乐不影响战术反馈；不依赖配音演员、剧情演出和大量人物台词。

如果一种视觉效果必须由人手逐图纠错才能成立，就改成程序几何或删除。图像生成用于有限母版，不是把不受控的大规模素材一致性当计划前提。

## 14 AI 对手与发行内容

对手 AI 使用玩家相同的命令入口、预算、视野、生产工时与完整蓝图。使用明确策略与效用评分，不把训练大型模型当项目依赖。

AI 需要具备：使用若干构筑并调整比例；观察已发现敌情；选择矿点和中继站；保留守备；识别自己网络的关键节点；在不利交战时撤退；组织第二条路线；侦察分基地并攻击核心；避免持续投送补员到已发现死路。它不能读取隐藏核心位置或敌方完整状态来决策。不同风格体现在偏好机动、重装、范围或控制，而非读图作弊。

低难度减少多线能力和决策频率，正常难度完整执行公平规则。若提供资源加成的挑战难度，单独明确标识，不把它藏在“聪明”里。

最终发行应含：一个自由混战房间及其大厅、开局 AI 席位、自定义房间设置、可编辑官方预设、局外蓝图库、编制模板、训练场、独立新手教程、完整对局回放、战后统计、重连、快捷键设置、音量与特效强度设置。总阵营和玩家连接均最多六个；不同时运行多个房间，不把额外观战连接算成免费流量。训练场支持两种蓝图或编制、初始距离与地形的重复对战，输出损失军备和存活人数。

教程放独立流程，依次教授军团操作、蓝图、编制、节点、补员、据点、核心存续与撤退改装。正式对局不常驻教学文字。战报优先解释军备交换、断援时间、核心损失与部队构成，不增加据点胜利分或只有开发者看得懂的计数器。

不把剧情战役、角色演出、航海与空军、外交条约、拍卖交易、匹配天梯及大量非对称阵营列入这次发行目标。完整发行品质来自既定核心的完整度，不等于加入所有 RTS 子系统。

## 15 核心重写决策与代码边界

### 15.1 决策与工作方式

在现有仓库的新开发分支中重写玩法核心，直接用新世界模型替换旧模型。旧版通过 Git 历史、明确的基线提交和可运行发布产物保留；不在新版运行时同时维护两套玩法，不复制一个长期存在的 `legacy/` 游戏。未来开始实施时再建立分支和基线，本轮不操作。

重写理由是旧 `Province` 同时承载建筑、所有权、经济、驻军和局部战斗，已经与独立建筑、持久军团和开放战场相冲突。禁止用“新军团转旧地块”“新网络伪装旧产线”维持旧逻辑。函数应该输出 C 时，直接重写生产方并修改所有调用者使用 C，不留下只为旧语义服务的 A→C 转换。

复用以职责为单位，不以文件必须原封不动为目标。一个文件中仍正确的数学、弹道或连接算法可以保留；依赖旧世界的遍历、参数和分支必须改写。现有 TypeScript、Phaser、WebSocket 与资源生产工具继续使用，不先更换引擎、增加通用 ECS、事件总线、微服务或新的 UI 框架。

开发中不要求旧完整游戏界面始终能运行。新核心早期使用固定场景、点线调试画面和真实联机客户端验证；正式 UI 就绪后替换调试入口。调试场景调用同一套模拟，不另造简化版游戏规则。当前类型检查覆盖整个 `src`，默认测试会发现整个 `tests`；因此阶段 1 切换模型时，就必须把不能直接使用新模型的旧消费者及专属夹具从工作分支清退，不能只停止导入后继续留在目录中。

### 15.5 防止新旧逻辑并存的完成条件

1. 每个业务概念只保留一个正式状态来源、一个执行入口。模拟、AI、UI 与网络都使用新对象，不双写新旧字段。
2. 每阶段同步修改类型、生产方、调用方、导出、测试与相关资源。不能以增加可选字段、类型断言或空壳旧函数掩盖尚未迁移的调用者。
3. 确实需要的边界转换只限明确用途，例如屏幕／世界坐标、规范化网络编码、快照序列化和只读视图汇总；不得据此保留旧玩法模型，也不建立通用转换框架。
4. 替换范围中的旧调用链在阶段结束前删除。分支可以暂时只有调试入口，但该阶段的完整类型检查、构建和当前默认测试必须通过；不能靠扩大 `exclude`、`any`、旧类型空壳、跳过全部旧测试发现或兼容开关伪装成迁移完成。
5. 收尾搜索旧类型、旧命令与字段，并逐一解释剩余引用。允许历史文档中出现旧词，生产代码不能仍依赖旧业务；同名新语义需在审阅中明确区分。
6. 新版构建只包含一套模拟。旧存档和旧回放不迁移进新模型，使用对应旧构建查看或明确提示不支持；不为已取消玩法增加兼容读取器。

这些条件不是行数竞赛。新增军团与蓝图需要合理代码，但不应出现为了保住旧调用方式而层层包装的增长。每阶段报告保留、替换和删除了什么，并检查最常用调用链能否直接读懂。

## 16 联机与 3 Mbps 带宽计划

### 16.1 已确认容量与同步方式

目标是**一台服务器总出站 3 Mbps、一个房间、最多六个玩家连接**。这里统一按十进制计算：3,000,000 bit/s ÷ 8 = 375,000 B/s，约 375 kB/s；不是每位玩家各有 3 Mbps。静态网页、图片、回放下载和同机其他服务都会共享出口。阿里云说明购买的公网带宽为出站带宽，控制台单位为 Mbps。[阿里云带宽说明](https://www.alibabacloud.com/help/en/ecs/user-guide/network-bandwidth)

保留服务器权威指令同步：服务器验证并排序命令，各端用同一初始状态、规则版本和完整指令帧运行模拟。模拟维持 30 Hz，正常对局不广播全部士兵位置、血量或每颗弹体。兵力增加主要提高计算与快照成本，不直接把日常传输量乘以士兵数量。

蓝图草稿、镜头、选框、拖动预览留在本地；发布、建造、改编、改装和军团命令进入权威帧。自动寻路、射击、补员、节点连通和生产由共享确定性模拟计算，不包装成每人每帧的位置更新。AI 只在服务器产生战略指令，其指令计入房间总流量；AI 本身不增加网络接收者。

当前完整世界重放可实现普通战争迷雾显示，但客户端持有敌方状态，不能保证阻止修改客户端开图。按休闲自由混战与 AI 对战定位继续使用，不宣称具备竞技反开图能力。若以后要求严格排名竞技的秘密状态，再单独设计按视野下发状态，不把那套网络模型混进本次重写。

继续发送完整空帧：缺少网络消息不等于该步无命令。将来只有实测包开销成为问题时，才考虑把少量连续 tick 合在一个消息中，保留每步边界，并计入增加的输入延迟。本次不把降低模拟频率作为省带宽手段。

### 16.4 预算与可复核估算

服务器出站的近似公式为：

`N × (F × E + C × L + H) + C真人 × A + P + R + S + O`

其中 N 是在线接收者数量，F 是每秒帧数，E 是帧外壳字节数，C 是**全房间**每秒确认命令总数，L 是每条命令平均附加字节数，H 是每秒每客户端摘要等小消息，A 是只返回提交者的确认字节数，P 是蓝图发布等大命令的额外广播量，R 是全部恢复传输，S 是静态下载，O 是协议开销与同机其他出站。不能漏算广播乘以 N，也不能把全房间 C 再误乘玩家输入数。

以下是有意留余量的计划预算，不是当前实测达标值；1 kB = 1000 B。

| 出站用途 | 正常对局预算 | 处理原则 |
| --- | --- | --- |
| 指令帧、结果与摘要 | 60 kB/s，约 0.48 Mbps | 最高优先级；短时密集指令可借用低优先级额度 |
| 所有客户端合计恢复 | 140 kB/s，约 1.12 Mbps | 全房间共享，不是每客户端各 140 kB/s；密集指令时降低 |
| 大厅与其他游戏控制 | 10 kB/s，约 0.08 Mbps | 不重复广播无变化的状态 |
| 比赛期间游戏静态下载 | 40 kB/s，约 0.32 Mbps | 聚合上限，优先利用缓存；不是每个下载连接各自上限 |
| 协议、重传与同机其他服务余量 | 125 kB/s，约 1 Mbps | 不当作游戏随时可用额度；通过出口实测核实 |
| 合计 | 375 kB/s，约 3 Mbps | 游戏应用载荷计划控制在 250 kB/s 内 |

预算需由一个房间级发送预算加静态服务端的聚合下载控制落实；只检查每个 socket 是否积压，或只给每条下载连接限速，都不能限制全服务器总量。实时消息优先于恢复，恢复优先于非必要下载。发送端先按实际序列化 UTF-8 字节进行保守的入队计量，另测压缩后与系统出口字节；不假设固定压缩率，也不用 `bufferedAmount` 充当网络流量计。不改变其他站点策略；未来部署时若同机其他服务持续超出余量，应先限制游戏低优先级传输并报告实际可用容量，不能宣称任意共享负载下仍有保证。

举例假设六个真人、30 帧/秒、每帧外壳 60 B、全房间每秒 30 条命令、每条 200 B、每端每秒附加 200 B、每条提交确认 100 B，则应用实时流量约为 `6 × (30×60 + 30×200 + 200) + 30×100 = 51,000 B/s`，即 0.408 Mbps。六人平均每人每秒五次正式操作已经是较密集的持续输入。短时提高到全房间每秒 120 条时约为 168,000 B/s，即 1.344 Mbps；此时暂停或缩减快照和下载，不能仍把所有表格额度同时用满。

上述示例不包含大蓝图发布和协议开销，最终使用实际 UTF-8 消息及压缩后传输字节测量。它说明不用同步所有人的每帧位置也能表达大量操作，不是承诺固定消息大小或真实网速。

### 16.5 快照压缩与恢复突发

服务器每秒保存快照是内部恢复准备，不代表每秒发送快照。恢复载荷只包含影响未来模拟的状态：士兵唯一实体、蓝图及仍被成员／任务引用的旧版本、军团、任务进度、军备、节点、随机状态、核心施工与淘汰状态。纹理、选框、动画、装饰残骸和可稳定重建的缓存不进快照。

地图静态数据按内容版本识别，拥有同版本地图的重连客户端可复用；新页面仍必须获得完整权威地图或已验证完全一致的地图数据，不能仅假设各浏览器用同一种子生成的地图相同。

当前 `server/index.mjs` 已启用 `perMessageDeflate`、1024 B 阈值和无上下文接管。先沿用“大消息压缩、小帧不压缩”的路线，不在其外再叠加 gzip 或默认更换二进制格式。压缩有 CPU 和内存成本，需在部署环境测序列化、压缩耗时与实际节省量。[ws 官方压缩说明](https://github.com/websockets/ws#websocket-compression)

恢复应采用明确的应用消息分块，初值每块未压缩数据约 8–16 KiB，配合共享发送预算，让不同客户端的实时小帧能在批量发送之间得到处理。WebSocket 底层自动拆包不等于应用消息可被重新排序；已经塞进 socket 的大队列无法靠随后标记“高优先级”插队。分块不产生第二套世界模型，只是传输同一份固定 tick 快照。

每个客户端同一时刻只保留一个恢复任务。完整接收并校验快照后原子替换本地世界，再按连续 tick 重放期间积累的命令；不能先应用半份世界。恢复任务记录起始 tick、状态版本、规则版本、块序号和完整性校验，并保留现有 `processed` 已确认指令序号及未确认指令去重，避免恢复后重复扣款或发布。后续帧进入该恢复任务的独立暂存，不能仍经旧 `Replica.waiting` 路径丢弃；收到晚到的旧任务数据不能覆盖新任务。

示例：若一份压缩后快照为 500 kB，在可用于恢复的出口吞吐为 140 kB/s 时，单人纯传输下限约 3.6 秒，六人同时恢复合计至少约 21.4 秒，尚未计排队、解压和追赶。500 kB 是预算示例，不是新快照测量结果。按未压缩字节保守入队时，实际排程须用序列化大小除以分配预算，可能比上述物理下限更长；不能据此承诺 21 秒恢复或直接确定日志长度。开局可在资源和初始状态就绪后统一开始计时；对局中的恢复则允许恢复者短暂等待，不能以暂停所有正常玩家来掩盖传输问题。

现有约 10 秒日志窗口、`Replica` 超过 180 帧请求恢复、恢复等待期丢帧的组合不能直接套到这种并发恢复。新版建议保留至少约 60 秒连续指令日志，并设置明确的内存上限；窗口须覆盖实测的最长传输和追赶时间。房间共享一份日志，仅保留最新可用快照及正在发送的固定快照，不因为日志为 60 秒就保存 60 份完整世界。等待的任务在实际开始传输时选择新快照，减少排队消耗窗口。接收快照期间缓存其 tick 之后的连续帧，恢复等待不重复发起完整同步；窗口失效时取消旧任务，调度一份新的快照，不叠加无限重试。快照体积与低优先级预算若不能满足窗口，应缩减状态冗余或延长有界窗口后重新验证。

### 16.6 下载与慢客户端

所有对局必需素材在准备阶段加载并缓存，内容带版本；地图中途不临时下载大图或声音。哈希资源可长期缓存，入口页面保持可更新。暂不要求 CDN 或新存储服务，先做好当前静态服务的缓存与聚合下载预算；同一机器上的 CDN 回源仍会占出口，不能把“有 CDN”视为天然解决。

排队指标同时观察应用队列、socket 缓冲和客户端落后帧数。浏览器 WebSocket 不自动提供完整背压控制，`bufferedAmount` 只表示发送端尚未发出的本地字节，不等于对方已处理或云出口没有拥塞。[WebSocket 流量控制说明](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API)、[bufferedAmount 定义](https://developer.mozilla.org/en-US/docs/Web/API/WebSocket/bufferedAmount)

慢客户端不能拖停其他客户端。优先暂停向它发送重复恢复数据，安排一次有效恢复；长期无法追赶时清楚显示重连状态，不能通过漏放已确认帧假装顺畅。现有 2 MiB 缓冲后断开只是最后保护，不是低延迟预算；不能靠无限增大缓冲或不断断开重连处理拥塞。已经进入 TCP 的数据不能撤销，需要从入队前控制。

### 16.7 运行与验收目标

| 场景 | 目标或测量口径 |
| --- | --- |
| 六方满额 | 约 1440 人含在途与储备，复杂兼容配装；压力目标，不是现有保证 |
| 模拟 | 30 Hz；在实际部署 CPU 测 tick 平均、P95 与最长耗时，不能持续欠账 |
| 渲染 | 1920×1080 常见交战争取 60 FPS，低特效模式保持可操作帧率 |
| 常态出口 | 六端实时应用流量争取不超过 60 kB/s，记录实际压缩、TLS/IP 与系统出口流量 |
| 输入延迟 | 分开测提交到服务器、提交到本地重放、浏览器呈现；P50/P95/P99，不只看平均流量 |
| 无拥塞输入目标 | RTT 约 100 ms 的规定测试条件下，提交到本地重放 P95 争取不超过 300 ms；是目标而非现有成绩 |
| 恢复影响 | 一端恢复不使其余五端长期增长积压；相比同条件无恢复基线，其他端 P95 延迟增量争取不超过 100 ms |
| 一致性 | 发布蓝图、断网、改装和补员途中恢复，Node、浏览器与部署 Linux 同帧摘要一致 |

沿用现有限速验证框架，重建新场景：先验证单恢复与基本命令，再在完整核心就绪后运行六端满额长局、集中交战、密集下令、六人同时重连、下载竞争和一个慢客户端。网络测试至少覆盖 60 分钟模拟与晚局恢复，并检查更长局的状态／日志是否持续增长；采用多个分开的服务与客户端进程，浏览器呈现与部署 Linux 另做对应检查。仅当相关功能改变、测试失败或疑点未解决时重复扩大测试。

必须真正限制**六端共享的服务器总出口**，加入规定 RTT、抖动和至少一种轻度丢包条件；记录 WebSocket 载荷、协议后总字节、压缩 CPU、发送队列、恢复耗时、tick 耗时和帧积压。用单个浏览器或每客户端各 3 Mbps 限速通过，均不算验收。

优化顺序是空间查询与军团路径共享、减少无用状态、发送调度和缓存、必要的压缩调参，再看实测热点。地图缩放只减少绘制，不改变实际参战人数。若无容量上限的配件组合产生过多弹体，应设计可解释的效果与作用次数边界、优化计算或调整公开人口，不能静默丢攻击或恢复地块参战配额。

## 17 核心重写顺序与删除时点

以下是完整发行目标的实现顺序，不是删减版玩法。每阶段都有可检查出口，并列明何时删除对应旧路径；正式联机从新模型建立时接入，不留到最后。

| 顺序 | 实施内容与依赖 | 清退或防止重新引入的旧职责 | 阶段完成判据 |
| --- | --- | --- | --- |
| 0 基线与规则 | 记录旧版本可运行基线、规则、资源清单；确认本文件中的状态、付款和胜负合同 | 不复制长期旧游戏目录；旧版留在 Git 与发布产物 | 保留／重写／删除清单准确；新旧版本与存档不混用 |
| 1 新模型和网络骨架 | 重写 `types/world/commands/snapshot` 的基本结构；直接接 `lockstep/Room/GameClient/Replica`；固定地图、军团与点线场景 | 先提取需要的纯规则，再清退其余旧模型消费者、入口、导出及专属测试，包括旧 UI、战斗、AI 与研究任务；移除权威步进对旧 AI 的调用 | 完整类型检查、构建与当前默认测试通过；两客户端军团命令、去重、缺帧和恢复一致；所有真实操作走权威入口 |
| 2 连续地图与军团 | 地形、建筑占地、导航、唯一士兵表、前后排软跟随与军团命令 | 地块邻接行军、士兵容器搬运、半队下令、局部战场坐标和固定队形算法 | 绕建筑、穿狭道、前排受阻、后方突袭及撤退正确；同一日志跨环境重放；调试视图直接读新实体 |
| 3 开放战斗与装备规则 | 移植适用枪剑、弹道、效果、防护与属性；所有成员在统一空间参与 | 旧 Battle/预备队/Fighter 分身、参战配额、province 目标筛选 | 固定完整配装场景能交战、侧袭和压制；无单兵指令，伤害和恢复一致 |
| 4 自由建筑与节点网络 | 新建造／取消任务、多核心、节点图、资源矿与中继站；接完整核心存续与即时淘汰 | 地块建筑与所有权、旧施工返款语义、领土路线 | 单链可断、备用边有效、孤立核心可工作；最后核心被毁同帧淘汰，新核心完工顺序明确 |
| 5 蓝图与完整生产 | 不可变版本、军团编制、军备、人口、整兵定价排产、研究任务 | 工坊表、逐件到货与装配、未武装出征、旧生产命令和相关 UI 资源引用 | 配比不超造、不饿死昂贵行；换版不改已开工任务；两兵营同帧不重复扣费占人 |
| 6 补员与返营整备 | 同网运输、安全出口、网外追随、团灭重建、改编与改装 | Shipment/Route/SupplyFlow、供应线编辑、旧补给路线和转运函数 | 断链与团灭不复制人；满人口可改编；改装中断可结算；所有中间阶段可恢复 |
| 7 正式 UI 与公平 AI | 军团 HUD、两编辑器、自由建造、迷雾、AI 侦察与核心攻防；取代点线入口 | 旧 GameUI/MapScene/interaction 的业务实现、装备组合军标、旧 AI；临时调试菜单退出发行入口 | 正式界面直接发新命令；六方可结束完整对局；AI 不读隐藏核心；没有旧模型转换 |
| 8 表现与完整内容 | 统一美术、声音、正式地图池、预设、蓝图库、训练场、教程、回放与统计 | 旧工坊／地块教程与过时发布资源；不再使用的临时文件 | 不依赖手工美术；界面在目标分辨率可读；训练场与正式局使用同一模拟 |
| 9 容量与发行收口 | 按第 16 节验证 3 Mbps、满人口长局、同时恢复；核对版本与未来部署回退 | 残留旧类型／旧命令调用、兼容开关、重复状态、无调用适配层、失效夹具 | 只构建一套新模拟；核心规则、网络、体验和资源检查完成，旧构建仍可独立回退 |

阶段 1 保留能独立工作的基础断言，把恢复、去重等适用测试直接改成新模型固定场景；完全依赖旧玩法的测试随旧代码退出，后续按新规则补充。阶段 2–8 的清单表示对应职责不得重新进入，不意味着旧代码继续保留到该阶段。纯算法若暂不需要移植，从基线 Git 阅读即可，不把整份旧实现复制回源码。

阶段 2–6 每加入影响未来行为的状态，都立即加入快照和至少一个有意义的恢复场景，不允许先做本地功能、最后再补同步。阶段 4 的核心淘汰是基础生命周期规则，阶段 7 验证完整六方流程，不能拖到画面完成后才决定游戏如何结束。

美术母版、界面布局和测试场景可在接口明确后并行制作，但不得各自编一套生产、伤害或费用算法。阶段 8 的正式视觉直接使用已经验证的玩法数据；保留适用资源不等于保留旧场景容器。

每阶段收尾依次做四件事：核对新行为；追踪调用者与导出；删除本阶段已替代旧路径；运行相称测试并记录未决问题。不要只统计新增文件或只检查差异；需要读最终调用链，确认不存在 `新对象 → 旧对象 → 新结果` 的绕行。无关逻辑与注释保持原样。

新版发布时拒绝旧客户端加入；旧回放使用对应旧构建或明确提示不支持。当前线上服务仍按现行合同运行，未来实际部署另行检查房间无人并准备回退；计划文档的提交与 GitHub 推送按用户明确指令执行，不代表开始核心重写或授权部署及线上配置修改。

## 18 验收与平衡方法

### 18.1 规则验收

| 场景 | 必须得到的结果 |
| --- | --- |
| A10 B20 C30，工时与价格差异很大 | 全部成员完整配装；需求计入在途在产；不超造，昂贵行不会被廉价行永久饿死 |
| V1 正在生产时发布 V2 | 已开工 V1 完成，后续 V2；旧新成员同一军团，无额外军标 |
| 两个兵营同一帧接单 | 缺额与人口只预留一次，军备不负数，不重复生产 |
| 中央节点被毁 | 真实下游暂停；订单进度保留；现役作战正常 |
| 有备用路径 | 仍受核心支持的设施继续工作，UI 不误报全线断开 |
| 两个核心互相断开 | 各自分量独立工作；跨分量增援不凭空传送 |
| 军团网内交火 | 不在前排即时刷兵；补员从安全出口走最后一段 |
| 网内运输中断或出口被毁 | 人员身份、位置与损失唯一，没有退款复制或穿墙落点 |
| 网外遭遇伏击 | 补员可损失，后续利用已知危险等待或改路，不全知避敌 |
| 军团团灭且仍有在途人员 | 停止给空锚点送兵，模板保留，人员归还安全集结点或承担真实损失 |
| 下调编制和合并军团 | 不删除或复制成员，不绕人口上限，不凭空迁移在途人员 |
| 便宜与昂贵版本反复切换 | 不能获得净军备或免费生命；未完成改装状态可解释 |
| 前排重装与后排抛射穿狭道遭后袭 | 无固定站位也能通过；后排不会自动穿越前排获得保护，后袭产生真实威胁 |
| 前排受阻、全灭或军团转向撤退 | 不为恢复队形反复换位；按明确跟随／撤退规则运行，无前排时不永久等待 |
| 最后核心被摧毁且仍有散兵、兵营和在建核心 | 同步立即淘汰，无重建等待；剩余实体不继续生产或战斗 |
| 同步新核心完工和旧核心被毁 | 按先施工完成、后战斗、再淘汰的固定顺序；仅已完成且战后存活核心计数 |
| 节点断联时恢复快照 | 后续生产、补员、军备与原始运行完全一致 |
| 多方同一步失去最后核心 | 统一淘汰后仅剩一方即胜；零方存活则平局，不依赖玩家遍历顺序 |
| 只剩两方且一方有隐藏分基地 | 不自动揭露核心，已知记录不泄露迷雾中的变化；AI 只能侦察寻找 |
| 安装全部兼容配件 | 不因总点数拒绝；价格、工时和性能代价可见，非法组合仍明确拒绝 |
| 六端同时重连并有正常指令与素材下载 | 出口按共享预算调度，恢复日志不缺帧、不重复扣费，不把每端限速误作总限速 |

### 18.2 不是只看一对一胜率

兵种与军团分别测等军备、等生产工时、等人口三种条件。等人口胜率高的重装未必等成本划算，基础兵不能只因单挑输就被误判无用。场景覆盖稀疏与密集、直线与绕侧、开阔与掩体、先手与遭遇、补员畅通与断援。

记录哪些配置成为所有场景的必选项、哪些组件从未被有效使用、混编是否比单一堆叠提供情境收益、撤退后是否有再投入价值、节点攻击能否改变接下来几十秒的战线。若结果总是唯一答案，先改产生支配性的机制，而不是给每个弱配置加一个零碎补丁。

自由混战另记录经济／兵力领先者的最终胜率、第三方介入收益、持续守家时间、核心被偷袭后的可反应时间、寻找最后分基地的耗时、军团团灭到补兵重建时间和总局长。分析用的全局实力信息不展示给玩家或供 AI 偷看。避免只用两个站桩军团验证整个游戏。

### 18.3 AI 可独立完成的检查

脚本生成场景、自动对战、多种固定种子、命令重放、快照恢复、资源与身份断言、界面截图、缩放可读性审查、图标对比、声音峰值和并发检查，均可由 AI 制作和执行。测试针对关键规则与实际失败，不给每个按钮写重复逻辑测试。

AI 对战能够筛出支配性构筑、死锁和明显不合理的节奏，截图能够筛掉遮挡与风格问题；它们不能证明真实玩家一定觉得好玩。计划不要求用户承担美术、关卡制作或手工修图，但不能把“全部由 AI 制作”表述成“无需任何玩家反馈也保证发行体验”。趣味性结论始终保留这个边界。

## 19 依据与取舍

项目现状依据为本仓库 `AGENTS.md`、`docs/planning/联机游戏设计.md`、`docs/planning/战斗与科技数值设计V1.md`、`src/sim/types.ts`、`src/sim/world.ts`、`src/sim/combat.ts`、`src/content/equipment.ts`、`src/render/MapScene.ts`、`src/ui/equipmentView.ts` 与现有美术脚本。网络依据另包括 `server/index.mjs`、`server/Room.mjs`、`src/net/Replica.ts`、`docs/verification/multiplayer-network.json` 与 `scripts/verify-network-load.mjs`。本轮仅核对现有记录并做预算计算，没有运行新的带宽或实战测试。

此前界面概念用于探索蓝图与编制交互，不是本轮规则的正式实现；涉及积分展示和固定阵形点阵等旧提案的部分以后按本文件替换。本轮只修改此总设计文档，不修改概念稿、游戏代码、现行联机合同或部署状态。

模块化单位编辑可参考 [Warzone 2100 的设计界面](https://betaguide.wz2100.net/design.html)，其身体、行走机构与武器选择说明了组件化设计的表达方式；ForgeFront 使用自己的枪剑、效果与防护规则，不照搬坦克结构。

本方案最需要在实施中验证的三处是：自动补员是否保留战损与侧袭价值；取消工坊后复杂构筑是否仍有充分代价；六方持续战场能否同时保持可读性和运行效率。三者决定游戏能否成立，优先级高于更换视角或增加精美插画。

## 20 已确认的补充玩法方向

以下补充规则与发行内容已于 2026-11-13 向用户汇报并获认可，纳入总设计。具体时间、费用、人数与算法参数作为初值在实现和测试中调整；本次认可不改变暂不修改游戏代码的工作范围。

| 规则组 | 已认可的方向 | 对应章节 |
| --- | --- | --- |
| 网内与网外补员限制 | 网内需同一网络、安全稳定落点和运输耗时；交战中从后方步行补入；网外小批跟随、遇已知封锁等待；补员不占点、不提供独立战略视野 | 5.3、8.1–8.3 |
| 团灭与改编 | 团灭后停止续送，需手动点重建；拆合、转编和退役仅在安全整备区进行 | 4.3、7.3、8.4 |
| 兵力规模 | 每军团最多 60 人、每人最多 8 军团、总人口 240，储备／在途／在产也计名额；常用 4–6 军团和 25–45 分钟为目标 | 2、4.1 |
| 蓝图与生产细则 | 草稿需发布，已开工锁旧版；自动补缺额与优先级；开工全额付款、按未完成比例退款，兵营被毁损失在产与储备 | 3.3、7.2–7.3 |
| 节点与建造 | 断网停生产、采矿、研究与整备，现役和防御仍作战；重连启动时间、单核心施工并行数、建造警戒距离与施工时间 | 6 |
| 收入与恢复费用 | 一份基础收入、不随核心数叠加；矿点不枯竭；改装收新增装备加工费、不全额回收；治疗另外收费并可返营自动休整 | 7.1、9 |
| 中立据点用途 | 作为不可摧毁、可占领的中继站，需要连接核心；争夺时暂停支持，不另给收入或胜利分 | 10.3 |
| 战斗与地形 | 林地减视野／速度、掩体减命中、地形阻直射；无友伤、己方不挡弹；敌军装备仅显示已观察信息 | 5 |
| 软分组执行边界 | 无前排时正常行动、撤退解除后排等待、前排受阻时后排自卫；具体距离与速度调节方式 | 4.2 |
| 其他发行内容 | 对称装备库、官方预设、局外蓝图库、训练场、回放、地图池与科技调整等完善项，作为完整发行的配套范围 | 1、3.4、9、13–14 |

实施时优先验证补员限制、团灭后的处理和人口上限，它们对玩家操作与战损感受的影响最大。若测试需要实质改变已确认行为，再明确说明变化；常规秒数、价格和参数调优不另建立重复审批流程。
